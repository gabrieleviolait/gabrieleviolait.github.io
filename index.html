Approccio

Uso GitHub come spazio pubblico per documentare progetti reali, condividere codice selezionato e mostrare l’evoluzione del mio lavoro tecnico.


Mantengo separati codice pubblico, componenti privati, configurazioni sensibili, ambienti personali, database, credenziali e file non destinati alla pubblicazione.

Stato dei progetti

Pubblicazione progressiva

A partire dal 2026 sto riordinando e pubblicando progetti selezionati, README e documentazione.

Documentazione prima di tutto

Alcuni repository sono dimostrativi, sperimentali o in evoluzione: il README resta la fonte migliore per stato, limiti e utilizzo.

Separazione tra pubblico e privato

Non tutto il codice personale viene pubblicato. Alcuni progetti restano privati per sicurezza, maturità o natura dell’infrastruttura.

Sicurezza, privacy e responsabilità

I repository pubblici non devono contenere chiavi API, token, file .env, credenziali, database personali o configurazioni private. I progetti sono forniti principalmente a scopo dimostrativo, educativo, professionale o sperimentale. Salvo diversa indicazione, il codice è fornito “as is”.
